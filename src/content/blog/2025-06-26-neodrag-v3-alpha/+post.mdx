After months of rebuilding from scratch, I'm releasing the **Neodrag v3 Alpha**. This isn't an incremental update - it's a fundamental rethink of how drag-and-drop libraries should work.

## The New API

v3 moves from an options object to a plugin-based approach:

{/* prettier-ignore */}
```javascript

draggable(element, [
  axis('x'),
  grid([20, 20]),
  bounds(BoundsFrom.parent())
]);
```

Everything is a plugin now - axis constraints, grid snapping, boundaries, event handling, custom behaviors. You mix and match only what you need.

**Framework examples:**

```svelte
<!-- Svelte -->
<div {@attach draggable([axis('x'), grid([20, 20])])}>
  Horizontal grid snapping
</div>
```

```tsx
// React
function Card() {
  const ref = useRef(null);

  useDraggable(ref, [bounds(BoundsFrom.viewport())]);

  return <div ref={ref}>Constrained card</div>;
}
```

```vue
<!-- Vue -->
<template>
  <div v-draggable="[axis('y'), grid([15, 15])]">Vertical movement</div>
</template>
```

```tsx
// SolidJS
function Card() {
  const [ref, setRef] = createSignal();

  useDraggable(ref, [bounds(BoundsFrom.viewport())]);

  return <div ref={setRef}>Constrained card</div>;
}
```

```tsx
// Vanilla JS
const element = document.querySelector('.draggable');

new Draggable(element, [
  axis('x'),
  grid([20, 20]),
  bounds(BoundsFrom.parent()),
]);
```

## Comparing to v2

Here's how the same functionality looks in both versions:

**Basic dragging:**

```javascript
// v2
draggable(element, {
  axis: 'x',
  grid: [20, 20],
  bounds: 'parent',
});

// v3
draggable(element, [axis('x'), grid([20, 20]), bounds(BoundsFrom.parent())]);
```

**Complex configuration:**

```javascript
// v2: Single options object
draggable(element, {
  axis: 'x',
  bounds: 'parent',
  grid: [10, 10],
  handle: '.drag-handle',
  onDrag: (data) => updatePosition(data),
});

// v3: Plugin array
draggable(element, [
  axis('x'),
  bounds(BoundsFrom.parent()),
  grid([10, 10]),
  controls({ handle: ControlFrom.selector('.drag-handle') }),
  events({ drag: (data) => updatePosition(data) }),
]);
```

## Key Differences

**Reactivity:**
v2 had automatic reactivity - you could use getters and it would automatically update. v3 uses manual reactivity for better performance:

```javascript
// v2: Automatic
let currentAxis = 'x';
draggable(element, {
  get axis() {
    return currentAxis;
  }, // Auto-reactive
});
currentAxis = 'y'; // Automatically updates

// v3: Manual compartments
let currentAxis = 'x';
const axisComp = new Compartment(() => axis(currentAxis));
draggable(element, [axisComp]);

currentAxis = 'y';
axisComp.current = axis(currentAxis); // Manual update
```

**Event handling:**

```javascript
// v2: Built-in callbacks
draggable(element, {
  onDrag: (data) => console.log(data.offsetX, data.offsetY),
});

// v3: Events plugin
draggable(element, [
  events({
    drag: (data) => console.log(data.offset.x, data.offset.y),
  }),
]);
```

**Bundle impact:**

- v2: 2.2KB for everything, whether you use it or not
- v3: 3.5KB core + only the plugins you import (tree-shakable)

## The New Architecture

Under the hood, v3 is built like a mini-framework with several key systems:

**Core as peer dependency:** `@neodrag/core` is a peer dependency across all framework packages. This enables better deduplication (one shared core) and consistent behavior in meta-frameworks like Astro where multiple framework packages might be used together.

**Event delegation:** Instead of 3 listeners per draggable, there are 3 total listeners that handle all draggables through delegation:

```javascript
// v2: 300 listeners for 100 draggables
for (let i = 0; i < 100; i++) {
  draggable(elements[i], { axis: 'x' });
}

// v3: 3 listeners total, regardless of count
for (let i = 0; i < 100; i++) {
  draggable(elements[i], [axis('x')]);
}
```

**State management:** Each draggable instance maintains isolated state, and plugins can store their own state:

```javascript
const counterPlugin = unstable_definePlugin(() => ({
  name: 'counter',

  setup() {
    return { moveCount: 0 };
  },

  drag(ctx, state) {
    state.moveCount++;
    console.log(`Move #${state.moveCount}`);
  },
}));
```

**Error isolation:** Plugin errors don't break the entire drag interaction:

```javascript
const buggyPlugin = unstable_definePlugin(() => ({
  name: 'buggy',
  drag() {
    throw new Error('Oops!');
  },
}));

// Other plugins continue working normally
draggable(element, [
  buggyPlugin(),
  axis('x'), // Still works
  grid([20, 20]), // Still works
  events({
    // Still works
    drag: (e) => console.log('Normal dragging'),
  }),
]);
```

**Effect system:** Plugins can schedule effects that run after the drag update:

```javascript
const shadowPlugin = unstable_definePlugin(() => ({
  name: 'shadow',

  drag(ctx) {
    ctx.scheduleEffect(() => {
      // Runs after position is applied
      element.style.boxShadow = `${ctx.offset.x}px ${ctx.offset.y}px 10px rgba(0,0,0,0.3)`;
    });
  },
}));
```

## Custom Plugins

The plugin architecture makes extending behavior straightforward:

```javascript
// Simple logging plugin
const logger = unstable_definePlugin(() => ({
  name: 'logger',
  start: () => console.log('Started'),
  drag: (ctx) => console.log(`At ${ctx.offset.x}, ${ctx.offset.y}`),
  end: () => console.log('Ended'),
}));

// Magnetic snapping
const magnetic = unstable_definePlugin((snapPoints, threshold = 50) => ({
  name: 'magnetic',

  drag(ctx) {
    const nearest = snapPoints.find(
      (point) =>
        Math.abs(ctx.offset.x - point.x) < threshold &&
        Math.abs(ctx.offset.y - point.y) < threshold,
    );

    if (nearest) {
      ctx.offset.x = nearest.x;
      ctx.offset.y = nearest.y;
    }
  },
}));

// Usage
draggable(element, [
  logger(),
  magnetic([
    { x: 100, y: 100 },
    { x: 200, y: 200 },
  ]),
]);
```

## Dynamic Behavior with Compartments

Compartments handle reactive updates efficiently:

```javascript
// Basic compartment
let currentAxis = 'x';
const axisComp = new Compartment(() => axis(currentAxis));

draggable(element, [axisComp]);

// Update manually
currentAxis = 'y';
axisComp.current = axis(currentAxis);
```

**Conditional plugins:**

```javascript
// Enable/disable grid snapping
let useGrid = false;
const gridComp = new Compartment(() => (useGrid ? grid([20, 20]) : null));

// Multiple dynamic settings
let settings = { axis: 'x', constrain: true };
const settingsComp = new Compartment(() => {
  const plugins = [axis(settings.axis)];
  if (settings.constrain) {
    plugins.push(bounds(BoundsFrom.parent()));
  }
  return plugins;
});

draggable(element, () => [gridComp, settingsComp]);
```

## Why I Rewrote v2

The v2 architecture had some fundamental limitations:

- **Monolithic bundle** – you paid for features you never used
- **Performance issues** – 3 event listeners per draggable + automatic reactivity overhead
- **Limited extensibility** – adding custom behavior required hacks
- **Fragile error handling** – one plugin error could break everything

Instead of patching these issues, I decided to rebuild with a better foundation.

## Migration Path

Most migrations are straightforward - you're mainly converting an options object to a plugin array. The reactivity changes require more work since it's now manual, but most projects can migrate in under an hour.

For complex reactive scenarios, you'll need to identify what was automatically reactive in v2 and create compartments for those values in v3. The manual approach gives you better performance and more predictable behavior.
