Heya friends! 👋 **neotraverse 0.7** is out, and it's a chunky one. If you don't know it yet, [neotraverse](https://neotraverse.puruvj.dev) is my zero-dependency, TypeScript-first rewrite of the classic [`traverse`](https://github.com/ljharb/js-traverse) — the little library that walks and transforms every node in an object tree. It's a **drop-in replacement**: swap the import and you're done.

This release does three big things: it makes neotraverse **safe to run on untrusted data**, makes the modern build **ridiculously fast**, and ships a proper **docs site** at [neotraverse.puruvj.dev](https://neotraverse.puruvj.dev). Let's dig in.

## 🔒 It's now prototype-pollution-safe

Object-walking libraries are the classic home of [prototype pollution](https://neotraverse.puruvj.dev/blog/the-vulnerability-run), so I put neotraverse through a deep, adversarial security audit. The fun part? The _obvious_ gadget didn't fire — but a couple of less-obvious ones did.

The headline one: `JSON.parse('{"__proto__":{"isAdmin":true}}')` produces an object with an **own, enumerable** `__proto__` key (unlike an object literal). The old `clone()`/`map()` copied that key with `dst[key] = src[key]`, which fires the `__proto__` setter and grafts attacker data onto the clone's prototype:

```js
// before 0.7 😱
const evil = JSON.parse('{"user":"bob","__proto__":{"isAdmin":true}}');
oldClone(evil).isAdmin; // true
```

In 0.7, every write sink (`set`, `clone`, `map`, `update`) refuses to mutate a prototype — the value is preserved as an inert own property instead:

```js
// 0.7 ✅
const evil = JSON.parse('{"user":"bob","__proto__":{"isAdmin":true}}');
traverse(evil).clone().isAdmin; // undefined
({}).isAdmin;                   // undefined — global prototype untouched
```

Legit prototypes are still preserved (a class instance is still an instance after cloning), and `get`/`has` only ever follow own properties. I wrote up the whole investigation — including why the first answer was wrong — in [**The vulnerability run**](https://neotraverse.puruvj.dev/blog/the-vulnerability-run). There's also a brand-new 42-case regression suite so this can never silently come back.

Oh, and there's a new opt-in **DoS guard** for deeply-nested hostile input:

```js
traverse(untrusted, { maxDepth: 1000 }).clone(); // catchable RangeError instead of a stack overflow
```

## ⚡ The modern build got *ridiculously* fast

Hardening usually costs performance. This time it bought some.

I re-architected the **modern** build's traversal engine. The old design allocated, for **every single node**, a context object _plus a fresh closure for each method_ (`update`, `remove`, `before`, …) _plus_ a `modifiers` object _plus_ a copy of the path array. The new design:

- makes the context a **class with prototype methods** — one allocation per node instead of a dozen;
- derives `ctx.path` **lazily** from the parent chain, so `forEach`/`map`/`clone`/`reduce`/`nodes` never pay for a path copy they don't read;
- clones with a **`Map` for O(1) circular detection** instead of a linear scan;
- and a pile of smaller wins (single key-scan, hoisted hot locals, indexed loops).

The result, across the full operation × shape benchmark matrix:

> **~4.5× faster than `traverse`** on average (geometric mean), **up to ~7×** on individual ops, while allocating **3–5× less memory** per op.

You can poke at the live, interactive numbers (throughput _and_ memory) on the [**benchmarks page**](https://neotraverse.puruvj.dev/benchmarks) — they're generated by the committed benchmark and rendered straight from the JSON. For a **bundle-size** comparison, there's a [bundle-roast link](https://bundle-roast.puruvj.dev) right on that page too.

The default and legacy builds keep the original, battle-tested implementation untouched — only the modern context was rewritten, and the full test suite passes identically on both.

## 🔧 New toolchain, and one breaking change

- The build moved from **tsup → [tsdown](https://tsdown.dev)** (rolldown/oxc).
- The **modern** build now targets **ES2026** (no change to emitted bytes today — the source is ES2022 — just a future-proof ceiling).
- ⚠️ **Breaking:** the **legacy** build now targets **ES2015** instead of ES5. It's still CJS + ESM and a drop-in `traverse` replacement; only environments that needed literal ES5 (think IE11) are affected. Full browser/runtime support is in the [docs](https://neotraverse.puruvj.dev/guide#browser-runtime-support).

## Upgrading

It's a drop-in. Most of you just need:

```sh
npm install neotraverse@latest
```

If you're still on the original `traverse`, now's a lovely time to switch:

```diff
-import traverse from 'traverse';
+import traverse from 'neotraverse';
```

That's it! Go forth and traverse — safely, and fast. 💚

If you find a bug or have ideas, the repo's [on GitHub](https://github.com/PuruVJ/neotraverse). Catch you in the next one!
